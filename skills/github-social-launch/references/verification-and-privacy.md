# Verification, privacy and delivery

## What proves completion

Maintain a private matrix of projects × actual destinations. Mark a native post **scheduled_verified** only after opening its saved queue/detail and checking account, date/time/timezone, caption and image. Mark **published_verified** only for an actual live post inspected after publication. Prepared captions, drafts, a Schedule click and a success toast are intermediate states.

Verify Facebook and Instagram individually, and the LinkedIn personal profile and organization Page separately. For two projects on four destinations, a complete schedule has eight independently verified destination entries, even if Meta used fewer submission clicks. Partial availability is a partial result, not a reason to claim all channels succeeded.

For Meta rules record saved enabled state, selected channels, exact keyword, trigger semantics/scope, public reply/private message and URL. Reopen after saving. Distinguish active configuration from an authorized end-to-end delivery test. Do not count an unchecked channel, unsaved draft or an uninspected old ledger as current evidence.

Deliver a compact table with explicit local dates/times and timezone, plus rule status and any real missing item. Keep the next action concrete if blocked. Provide screenshots or local previews the user can inspect; do not place private account screenshots in a public repo. If handing off at the user's request, include exact skill location/repo, public assets, private state location and the authorized task; the receiving chat must reconcile live queues rather than replay the whole launch.

## What stays private

Account bindings, Page/business IDs, admin/inbox URLs, browser tab/session details, actual schedules, screenshots, message recipients, source chats and the filled ledger/profile are private operational context. Never include them in public skill files, release archives, production prompts or sample fixtures. Generic four-role templates and invented examples are portable; original account values are not.

Only approved public signature details may appear in a released skill. A source chat or public profile is not permission to add unrelated personal information. Keep credentials and cookies out of files, prompts, diagnostics and handoffs; a logged-in browser session is used through the approved control tool rather than exported.

The assistant/model processes what it reads; image services process their briefs/references; scheduling sends selected copy/images to the chosen platform; enabling a comment rule can send future platform replies under that rule. Explain these real effects without claiming that the entire workflow is offline. Do not create paid ads, subscriptions or account/security changes as a workaround for missing organic features.

## Reasoning checks using invented situations

- Saved Facebook-only rule + new Instagram request: add/verify Instagram without duplicating the rule or Facebook post.
- LinkedIn personal queue is populated but Page queue is empty: only the personal posts are complete. Schedule/verify the Page separately.
- Queue save is uncertain: inspect before retrying; a matching persisted entry resolves it without a duplicate.
- Requested day already contains unrelated content: preserve it and use the next permitted day, or resolve a fixed-window conflict.
- No native LinkedIn message automation established: return manual replies and say so; do not invent activation.
