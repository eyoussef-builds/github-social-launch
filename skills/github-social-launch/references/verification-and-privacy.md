# Verification, privacy and delivery

## What proves completion

Maintain a private matrix of projects × actual destinations. Mark a native post **scheduled_verified** only after opening its saved queue/detail and checking account, date/time/timezone, caption and image. Mark **published_verified** only for an actual live post inspected after publication. Prepared captions, drafts, a Schedule click and a success toast are intermediate states.

Verify Facebook and Instagram individually, and the LinkedIn personal profile and organization Page separately. For two projects on four destinations, a complete schedule has eight independently verified destination entries, even if Meta used fewer submission clicks. Partial availability is a partial result, not a reason to claim all channels succeeded.

For each repo, use the [SuperMod verification procedure](meta-keyword-delivery.md) and record four cells: Facebook comment, Instagram comment, Messenger incoming message and Instagram incoming message. Reopen saved workflows and verify both triggers, enabled channels, complete matching alias lists, exact repo URL, ordered replies, public child-comment parent and relevant limits. Record provider, connection/readiness and any overlapping native-rule outcome. An absent SuperMod connection means explicit skipped cells, not native fallback or completed coverage. A partial connection means partial coverage. Distinguish saved configuration from authorized real delivery tests.

Deliver a compact table with explicit local dates/times and timezone, plus rule status and any real missing item. Keep the next action concrete if blocked. Provide screenshots or local previews the user can inspect; do not place private account screenshots in a public repo. If handing off at the user's request, include exact skill location/repo, public assets, private state location and the authorized task; the receiving chat must reconcile live queues rather than replay the whole launch.

## What stays private

Account bindings, Page/business IDs, admin/inbox URLs, SuperMod instance/deployment URLs and connection details, browser tab/session details, actual schedules, screenshots, message recipients, source chats and the filled ledger/profile are private operational context. Never include them in public skill files, release archives, production prompts or sample fixtures. Generic four-role templates and invented examples are portable; original account values are not.

Only approved public signature details may appear in a released skill. A source chat or public profile is not permission to add unrelated personal information. Keep API keys, access tokens, app secrets, webhook secrets, credentials and cookies out of public files, prompts, diagnostics and handoffs; store service secrets only through the instance’s supported private secret controls. A logged-in browser session is used through the approved control tool rather than exported.

The assistant/model processes what it reads; image services process their briefs/references; scheduling sends selected copy/images to the chosen platform; enabling a comment rule can send future platform replies under that rule. Explain these real effects without claiming that the entire workflow is offline. Do not create paid ads, subscriptions or account/security changes as a workaround for missing organic features.

## Reasoning checks using invented situations

- SuperMod is absent: schedule the authorized posts, mark all four keyword cells skipped, keep a truthful manual/direct-link CTA and create no native keyword fallback.
- Only Facebook is ready in SuperMod: verify its comment and incoming-message cells, report the two Instagram gaps and preserve unrelated automations.
- A matching native responder exists: verify the replacement before disabling only that responder; if readiness is unresolved, keep the new workflow paused.
- Comment rules are already correct on both channels, but incoming-message rules are absent: preserve the comment rules, add SuperMod incoming-message triggers on both channels and verify the remaining two cells.
- Canonical `أداة جديدة` exists in comments and messages but `اداة جديدة` is missing: add the applicable no-hamza alias to both trigger types, verify both channels and reopen saved forms; changing public artwork is unnecessary.
- A canonical phrase has no plausible spelling alias: record the review and keep its precise phrase instead of inventing a broad match.
- Both triggers are active but no live test was authorized: report saved configuration and delivery untested; do not post a test comment or send a DM.
- LinkedIn personal queue is populated but Page queue is empty: only the personal posts are complete. Schedule/verify the Page separately.
- Queue save is uncertain: inspect before retrying; a matching persisted entry resolves it without a duplicate.
- Requested day already contains unrelated content: preserve it and use the next permitted day, or resolve a fixed-window conflict.
- No native LinkedIn message automation established: return manual replies and say so; do not invent activation.
